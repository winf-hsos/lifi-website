Installation

Haltet die Reihenfolge ein, manches baut aufeinander auf. Rechnet mit einem Nachmittag: Installationen laufen selten beim ersten Versuch durch, und das liegt nicht an euch.

Sobald OpenCode aus Schritt 4 läuft, könnt ihr ihn bei allem Weiteren um Hilfe bitten. Er kennt das Kursmaterial und kann euch durch die restlichen Schritte führen, Fehlermeldungen einordnen und prüfen, ob etwas fehlt. Wenn ihr trotzdem hängen bleibt, bringt die Meldung im Wortlaut mit in die Übung.

1. Python

  • Windows
  • macOS

Ladet den Installer von python.org/downloads und startet ihn.

Wichtig: Setzt im ersten Fenster das Häkchen bei „Add python.exe to PATH”, bevor ihr auf „Install Now” klickt. Ohne dieses Häkchen findet die Kommandozeile Python später nicht, und das ist der mit Abstand häufigste Stolperstein.

Prüfen: Startet die Eingabeaufforderung und tippt

python --version

Es sollte eine Versionsnummer erscheinen, etwa Python 3.13.1.

Auf dem Mac ist zwar eine ältere Python-Version vorinstalliert, die solltet ihr aber nicht verwenden. Ladet den Installer von python.org/downloads und startet ihn.

Prüfen: Öffnet das Terminal und tippt

python3 --version

Es sollte eine Versionsnummer erscheinen, etwa Python 3.13.1.

Merkt euch: Auf dem Mac heißt der Befehl python3 und nicht python.

2. Git

  • Windows
  • macOS

Ladet Git von git-scm.com/downloads und installiert es. Die Voreinstellungen des Installers könnt ihr durchweg übernehmen.

Mit installiert wird dabei Git Bash, ein Terminal, das ihr in Schritt 4 für OpenCode braucht.

Prüfen: In der Eingabeaufforderung

git --version

Tippt im Terminal einfach

git --version

Fehlt Git noch, bietet macOS von sich aus an, die Command Line Tools zu installieren. Bestätigt das und wartet, bis es durchgelaufen ist. Alternativ über Homebrew: brew install git.

3. Visual Studio Code

Ladet den Editor von code.visualstudio.com und installiert ihn. Beim ersten Start bietet er an, die Python-Erweiterung zu installieren. Nehmt das an.

Zwei Dinge, die ihr gleich ausprobieren solltet:

  • Ordner öffnen über Datei > Ordner öffnen. VS Code arbeitet immer mit einem Ordner, nicht mit einzelnen Dateien.
  • Terminal öffnen über Terminal > Neues Terminal. Dieses Fenster unten im Editor ist die Kommandozeile, in der ihr eure Programme startet und mit der ihr gleich weiterarbeitet.

4. OpenCode

OpenCode läuft im Terminal. Benutzt dafür das Terminal in VS Code.

  • Windows
  • macOS

Öffnet in VS Code ein Terminal und wählt oben rechts im Terminalfenster Git Bash aus. Dort:

curl -fsSL https://opencode.ai/install | bash

Im Terminal:

curl -fsSL https://opencode.ai/install | bash

Alternativ über Homebrew: brew install sst/tap/opencode.

Prüfen: opencode --version.

Anschließend müsst ihr OpenCode noch mit einem Sprachmodell verbinden. Wie das geht und welche Zugangsdaten ihr dafür bekommt, erfahrt ihr in der ersten Übung.

5. Brick Daemon und Brick Viewer

Beide bekommt ihr auf der Tinkerforge-Downloadseite. Ladet jeweils die Version für euer Betriebssystem und installiert sie.

Unter Windows sind es zwei .exe-Installer, unter macOS zwei .dmg-Pakete, die ihr öffnet und in den Programme-Ordner zieht.

Der Brick Daemon startet danach von selbst und läuft als Hintergrunddienst mit. Ihr seht ihn nicht, und das ist normal.

6. Das Modul lifi_hardware

Damit sprechen eure Python-Programme mit der Hardware. Im Terminal:

pip install git+https://github.com/winf-hsos/lifi-hardware.git

Auf dem Mac gegebenenfalls pip3 statt pip.

Das Paket bringt die Tinkerforge-Bibliothek als Abhängigkeit mit, die müsst ihr also nicht getrennt installieren. Und weil die Adresse mit git+ beginnt, holt pip das Paket über Git. Deshalb musste Git aus Schritt 2 vorher installiert sein.

Wenn im Lauf des Semesters eine neue Fassung des Moduls erscheint, holt ihr sie mit

pip install --upgrade --force-reinstall git+https://github.com/winf-hsos/lifi-hardware.git

7. Kursmaterial holen

Damit bekommt ihr die Wissensbasis des Moduls und die Anweisungen, nach denen sich euer Assistent richtet.

git clone <ADRESSE-DES-REPOSITORYS>

Öffnet den entstandenen Ordner anschließend in VS Code. Wenn im Lauf des Semesters etwas dazukommt, holt ihr euch den neuen Stand mit git pull.

8. Prüfen, ob alles zusammenspielt

Schließt ein Gerät per USB an und startet den Brick Viewer. Wenn dort euer Master Brick mit LED und Farbsensor auftaucht, ist die Installation vollständig. Klickt euch ruhig durch und schaltet die LED von Hand ein. Das ist noch kein Programmieren, aber es ist der Beweis, dass alles miteinander redet.

Wenn etwas nicht funktioniert

Die drei Fragen, die am häufigsten helfen:

  1. Läuft der Brick Daemon? Ohne ihn findet kein Programm die Hardware.
  2. Zeigt der Brick Viewer euer Gerät an? Wenn nein, liegt der Fehler vor eurem Code.
  3. Benutzt ihr python oder python3, pip oder pip3? Auf dem Mac fast immer die Variante mit der 3.
